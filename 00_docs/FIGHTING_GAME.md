# Fighting-game theory against the defender

The arena already borrows the vocabulary of a fighting game: a move, its counter, the attack on the counter, strikes that persist, a fight that changes in the second phase. This page takes the rest of the theory, the part about **making the opponent guess**, and asks of each idea the only question that matters here: does the gateway ever guess? Every row is measured through the real gateway in `12_arena/mixups.py` and pinned in `12_arena/test_mixups.py` (chain XA-27, bout B39). Run `python3 12_arena/mixups.py` for the table.

## Why a human defender can be mixed up and a wall cannot

In a fighting game the defender has one body. Blocking high leaves the low open; blocking a throw means not blocking a strike; reacting to the left side means the right side is late. Every offensive idea (conditioning, 50/50s, left/right, tick throws, option selects, okizeme) exploits the fact that the defender must choose, and chooses from a prediction. A wall does not choose. Every wall is checked on every call, so there is no "high" that leaves the "low" open: the typed-argument wall and the egress wall look at the same call. A wall reacts at frame zero, because the same call gets the same answer whatever came before. What is left for the attacker is the one part of the defender that does have a body: the human who reads what the gateway lets through, and any part of the defence that *learns*.

| idea | in the game | against the gateway | what GLITCH does | measured by |

## The defender's turn: conditioning and mix-ups as hardening

The same theory, used by the defence, deterministically (no decision is ever random; the audit must replay):

| move | what it does | measured by |
|---|---|---|
| **The table has teeth** (defender conditioning) | the operator plants decoy destinations on its own plane; the refusal for a decoy reads exactly like the refusal for any unlisted destination, so an attacker enumerating the table cannot tell a trap from a gap; touching one burns the principal at once | `Hardening.test_the_table_has_teeth_...`, the mutant that ignores the decoy table, the fairness test |
| **A wall looks like a whiff** (defender mix-up) | with opaque refusals on, an ordinary error is specific in the first phase and, after the second strike, an ordinary error and a security wall return the same words: the attacker loses its frame data; the record keeps the real reason | `Hardening.test_a_wall_looks_like_a_whiff_...`, the mutant with specific refusals, the fairness test |
| **Depth one** (anti-conditioning, AgentDojo `seen` profile) | a seen link is admitted once, and the result of that fetch admits nothing, so content cannot condition the policy a link at a time | `17_agentdojo/test_dojo.Hardening` |
| **The boss inside a task** (AgentDojo `glitch-boss`) | every security refusal is a strike; after two the model is told only "not permitted" (the attacker learns the policy from the reasons, through the model's retries); after four, writes are locked for the task and reads continue | `17_agentdojo/test_dojo.Hardening`; not yet run with a model |

## Where conditioning is real

Two parts of the system do learn from traffic, and both are named rather than hidden:

- The **`seen` link profile** in `17_agentdojo` lets a fetch follow a link the gateway itself delivered during the task. That is a conditioned state: content places a link, the policy admits it. It is reported as a separate row, off by default (`strict`), and on the benchmark's ground truth it buys 4 of 97 user tasks for no change in the security floor. It would be the first thing an adaptive attacker aimed at, which is why it now admits a link once and nothing from that fetch's result (depth one).
- The **governor** learns too, but only in one direction: strikes never go down on their own. Conditioning it can only make the fight harder for the attacker, which is the point of a ratchet.

## What this does not claim

The attacker modelled here plays scripted options through the real gateway; no model wrote the sequences. The human reader is outside the gateway's reach by construction, and the option-select row is the honest statement of that. A fighting game also has **reads on the player**: habits across many matches. The analogue, an attacker who learns one deployment's manifests and tables over weeks, is the adaptive-attacker item on the open-items page and has not been run.
